## What I learnt

**Spec Kit helped.** The structured specification and planning process made architectural decisions explicit before implementation. It also gave me something concrete against which to review the generated code.

**Verification remains essential.** Successful builds and tests don't establish that every architectural or security requirement has been met. The difference between testing configuration and testing actual server behaviour was a useful example.

**AI agent handovers need designing.** Antigravity reached its quota without updating task completion. Smaller implementation batches, incremental checklist updates and a persistent handover document should make this more manageable.

**Dependency security needs to be part of the workflow.** After pushing the repository, GitHub Dependabot reported 49 vulnerabilities, including five critical. These haven't yet been investigated or assessed for applicability. This is a reminder that dependency scanning complements builds, tests and code review.

## Reflection

The SDD process felt worthwhile. It gave structure to the work and made the generated implementation easier to evaluate.

The biggest lesson is that specification-driven development doesn't remove engineering judgement. It gives that judgement a clearer basis for reviewing decisions, testing outcomes and deciding what is genuinely complete.
